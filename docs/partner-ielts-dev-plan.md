## 1. 需求总览

### 1.1 四阶段功能矩阵

| 阶段 | 周期 | 核心交付物 | 功能数量 | 开发复杂度 |
|------|------|----------|---------|-----------|
| **Phase 1** | Week 1-4 | MVP 核心可用 | 12 个功能 | 🔴 高 |
| **Phase 2** | Week 5-8 | AI 全科教学闭环 | 10 个功能 | 🔴 高 |
| **Phase 3** | Week 9-11 | 彩蛋 + 社交 + 游戏 | 8 个功能 | 🟡 中 |
| **Phase 4** | Week 12-14 | AI Agent 雅思考官 | 7 个功能 | 🔴 高 |

### 1.2 功能优先级矩阵

```
        高影响力
            ▲
            │
     P0    │    P1
  (核心)    │  (重要)
            │
 ◄──────────┼──────────► 低难度        高难度
            │
     P2    │    P3
  (可选)    │  (延后)
            │
        低影响力
```

| 优先级 | 说明 | 功能 |
|--------|------|------|
| 🔴 P0 | 必须有，MVP 核心 | 学习日历、打卡计时器、双人进度对比、AI 评分看板、用户系统、页面框架、上传中心、新手引导 |
| 🟡 P1 | 重要，Phase 1-2 | AI 写作批改、口语对练、词汇工具、每日寄语、通知系统、勋章墙、纠音师、错题本 |
| 🟢 P2 | 增强，Phase 2-3 | 翻译工具、小游戏、心愿卡、学习广场、分级联赛、每日推荐话题 |
| ⚪ P3 | 探索，Phase 4 | AI Agent 完整功能（记忆/推送/群聊/网络学习） |

## 8. 风险与调整策略

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|----------|
| Supabase 免费额度耗尽 | 低 | 中 | Phase 1 完成后评估，按需升级 |
| AI API 响应不稳定 | 中 | 中 | 降级提示 + 本地缓存 + 重试 |
| 功能范围蔓延（Scope Creep） | 高 | 高 | 严格按 P0/P1/P2 优先级执行，不新增 P0 以外功能 |
| 移动端适配工作量超预期 | 中 | 中 | Week 4 预留 1 天专门处理响应式 |
| AI 批改质量不如预期 | 中 | 高 | Phase 2 早期做用户测试，及时调整 Prompt |

### 调整策略

- **每周站会**: 每周一评估上周进度，调整本周计划
- **P0 冻结**: Phase 1 开发期间不增加新功能
- **迭代评审**: 每个 Phase 结束后做一次产品评审，决定下个 Phase 优先级
